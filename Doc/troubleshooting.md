# 故障排查

[文档目录](README.md) · [安装](installation.md) · [使用指南](user-guide.md)

先区分“没有采到声音”“有录音但没转写”“有文字但没人物标签”。这三段有不同的状态和模型，重复点击分析不能修复麦克风权限问题。

## 快速检查

```sh
./scripts/audio-agent doctor
./scripts/audio-agent devices
./scripts/audio-agent status
```

检查当前资料目录、ffmpeg、Python 依赖和已有 ASR 模型，再查看 Web 的录音状态、错误提示与任务队列。`doctor` 不是 VAD/说话人真模型自检，也不能证明推理质量；相关状态在控制台功能区查看。以上命令不启动录音。

## 麦克风与分段

| 现象 | 检查与处理 |
| --- | --- |
| 打开页面后说话，没有任何录音 | 打开页面不会开麦；选择设备后明确开始监听 |
| 开始失败或没有 PCM 电平 | 核对设备精确名称、插拔状态以及启动宿主的麦克风权限；不要自动换成另一个设备 |
| 权限弹窗未出现，菜单栏等待 | 查看系统设置的麦克风/文件与文件夹权限。项目位于文稿时还可能需要文稿授权；系统提示由使用者本人处理 |
| 更新应用后再次请求权限 | ad-hoc 重建可能改变应用签名；重新核对请求的应用与目录后由用户确认 |
| 一直显示等待声音 | 当前门槛可能太高，先靠近麦克风并小幅调低；启用 VAD 时还需检测到人声 |
| 有声音，却没有逐字更新 | 当前在停顿结束片段后再转写；持续讲话期间不会像字幕流一样逐字刷新 |
| 安静时仍出现固定 5 秒文件 | 核对是否运行了 CLI `record/start` 连续缓存模式；Web/Mac 监听采用动态分段，不是该模式 |
| 多个短句合成一段 | 默认连续安静约 0.8 秒才结束；短于此停顿可能属于同段 |
| 连续声音约 10 分钟后停止 | 内存保护上限会保存当前段并停止，不能把它当成定时切片；检查持续背景声，再显式重开 |
| 点停止后还在计算 | 麦克风停止与已有任务结束是两回事；已经录下的片段会收尾 |
| 关闭菜单栏还在录音 | 退出客户端不停止后台；请用监听开关停止 |

收音门槛范围 −60 至 −18 dBFS，越接近 0 越不灵敏。滑块是触发门槛，**不会对已录音频做降噪**。电视与其他人声音足够大时仍会被录入；VAD 判断“是否像人声”，不判断是否属于目标谈话。更多背景见 [产品设计](product-design.md) 和 [模型配置](models.md)。

## 转写与模型

| 现象 | 检查与处理 |
| --- | --- |
| `No local Whisper GGML model found` | 指定已有 `AUDIO_AGENT_MODEL` 或正确的 `HANDY_MODELS_DIR`；程序不会自动下载 |
| 文件存在但提示不兼容 | 只支持当前适配的 Whisper GGML；不是所有 `.bin` 或 Handy 模型都兼容，改扩展名无效 |
| VAD 模型缺失 | 当前默认读取 Handy 包内 Silero v4；Web「录音设置」取消默认 VAD 后再开始。菜单栏无 VAD 开关，需在 Web 实际开始一次会话并刷新后沿用；新菜单栏连接尚无会话的后台时仍默认启用 VAD，重启组合后检查。不修改 Handy 文件绕过校验 |
| `onnxruntime` / `sherpa_onnx` 缺失 | 在同一 `.venv` 安装 `speech` extra；确认后台实际运行的 Python 路径 |
| `ggml_metal_buffer_init` 等 Metal 错误 | 检查运行环境与可用内存；在实际服务启动环境明确设置 `AUDIO_AGENT_USE_GPU=false` 可试 CPU。不会回退云端 |
| 超时 | 查看片段时长和队列；先用短的已知样例。ASR 默认 300 秒，可在 1–1800 秒范围配置；不无限延长 |
| 背景声产生错误文字 | 确认不是静音/音乐触发，调整门槛与 VAD；ASR 可能幻听，文字不是音频真实性保证 |
| 导入了 WAV 却没有自动文字 | 文件导入和目录监听默认只入库；选择录音后明确转写。自动说话人也不会补处理这些导入文件 |
| 队列持续积压 | ASR 与说话人串行；暂停不需要的自动说话人或停止新录音，等待收尾。检查是否持续收进电视等背景声 |

日志与中间产物可能含本地路径或音频关联信息，报错提交前请脱敏。不要把 `.data/` 整体附在公开 Issue 中。

## 人物与声纹

- “登记为我/登记其他人物”需要已完成分析且有有效声纹向量。按钮不再要求先点击试听按钮才能打开表单，但提交仍需本人试听后明确确认。
- 没有固定 5 秒登记门槛；1–2 秒可能有有效向量，但过短、重叠或不清晰仍可能提取失败。换清晰单人片段再分析。
- 本人可追加最多 10 条参考，其他人物仍每人一条。网页默认追加；明确选择替换会把整组换成当前一条。已有短参考不会自动被换掉，也不会偷偷收集最近语音。
- 可以主动补充 3–5 段不同常见说话方式的清晰本人参考，每条 10–20 秒只是建议；样本更多不保证更准确。移除录错、混入他人或质量差的样本，不靠重复登记同一声音凑数量。
- 达到上限先移除不合适的单条参考，再追加；不要误用整组替换来腾出一个位置。同一分析的不同 speaker 不能都登记为本人，需先核对分析和声音来源。
- `speaker_1` 只在当前录音中有意义，不保证下一段仍是同一个人。
- 自动区分默认关闭；开关开启期间，监听流程新成功转写的片段会排队，包括当前正在运行会话的后续片段，无需重启；不回填历史或导入文件。已有文字先显示，人物标签稍后补上。
- 分析完成却不显示“我”，可能因为模型不一致、参考太短、候选不足 2 秒、相似度/差距未达门槛；不要把门槛降到总能匹配来当成成功。
- 选择明确人数有助于已知场景，但“指定两人得到两人”不是自动人数识别的准确率验证。
- 人物参考库损坏会暂停自动匹配；保留备份并修复或通过 UI 明确重新登记，不能忽略错误继续猜身份。
- 样本状态的 `model_compatible: null` 表示没有在状态读取时核验当前模型，不是兼容性错误。旧版单参考仍可读取，首次实际修改才升级 v2；不要为了升级格式而删除原参考。

## 目录、端口与 UI

| 现象 | 检查与处理 |
| --- | --- |
| Web 可开但菜单栏连接失败 | Web CLI 默认 8765，菜单栏固定 8767；用 `web --port 8767`。已有其他服务占用时不要终止未知进程 |
| 提示音频库不一致 | CLI 覆盖、环境变量和保存设置可能选了不同库。按“存储位置”核对解析优先级 |
| 移动项目后应用启动失败 | `.app` 绑定构建时项目路径；恢复路径或在新位置重新安装依赖并构建 |
| 保存设置提示会话过期 | 后台重启会更换写令牌；刷新页面后再试 |
| 某些旧记录不见了 | 检查 24 小时保留范围、资料目录和会话筛选；过期缓存不等于永久档案 |
| 存储切换按钮禁用 | 停止监听，等待导入/转写/说话人/设置提交完成；若使用 `AUDIO_AGENT_DATA_DIR` 固定路径先移除启动覆盖 |
| 提示旧资料库已迁移 | 使用新路径重启/重连，别直接删除迁移标记继续向旧库录音 |
| 非空目录不能选 | 当前只支持复制到空或新目录，不支持合并两个库 |
| 磁盘不足 | 默认保留至少 256 MiB 余量；检查空间与需要备份的缓存，不要盲目删库或模型 |

菜单栏启动后台的日志通常在当前资料库 `logs/menu-bar-service.log`；CLI 后台采音使用 `capture.log`。源码库更新不等于正在运行的 Python 服务或 `.app` 自动更新：前者需停止/重启以加载代码，后者需重新构建并打开。

## MCP 连接或读取

1. 先看客户端是否实际加载 `audio-agent`，不要把控制台页面“配置就绪”当成已连接。
2. 使用 stdio 命令和 `.venv/bin/python`，不要把 Web URL 作为 MCP HTTP endpoint。
3. 检查配置中的绝对路径、项目信任范围和运行环境；复制配置只是第一步。
4. 已有转写请用读取工具，不要为了“刷新”重复调用 ASR。
5. 游标过期/服务重启/换库后省略旧 cursor 重建；只取最近 `limit` 条的首次增量不是历史全量导出。
6. 同一 `document_key` 后补标签是更新，不应重复追加成新对话。

完整例子和错误语义见 [MCP 接入](mcp-integration.md)、[MCP 使用](mcp-usage.md)。
