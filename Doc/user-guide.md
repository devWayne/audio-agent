# 用户指南

本指南对应当前源码，核对日期为 2026-10-24。所有示例路径都是占位路径，不是某台电脑的实际资料位置。首次安装、运行环境与模型准备见[安装与启动](installation.md)和[模型说明](models.md)。

## 1. 先理解三件事

1. **打开应用不等于开始录音。** 需要主动点击“开始监听并自动转写”，或执行 CLI 录音命令。
2. **当前不是逐字流式识别。** 系统等待这一段声音结束，再运行本地模型。说完后停顿约 0.8 秒，之后还要加上排队和模型推理时间。
3. **这是默认保留 24 小时的本地资料库。** 想长期保存的文字请下载或复制到自己的文档；源录音需要另外备份。TXT 不会随每次转写自动生成。

日常使用可以选择两种模式：

| 模式 | 声音如何保存 | 何时识别 | 适合什么情况 |
| --- | --- | --- | --- |
| Web / 菜单栏监听 | 有效声音触发，停顿结束动态片段；安静不新建文件 | 本次新片段保存后自动转写 | 口述、讨论、及时查看文字 |
| CLI 连续缓存 | 默认每 5 秒保存一片；停止时保存剩余片段 | 另行执行转写或让 MCP 按需转写 | 希望先缓存，之后只识别需要的部分 |

两者使用同一类资料库，但不要同时抢占同一资料库的采音会话。MCP 自身没有开始录音工具；它读取已有资料，或对已保存音频按需识别。

## 2. 启动、连接与安全停止

### 2.1 打开 Web 工作台

在已经安装好依赖的项目目录运行：

```sh
./scripts/audio-agent web --port 8767
```

在浏览器打开 `http://127.0.0.1:8767`。命令行 `web` 的默认端口是 8765；本指南统一使用 8767，与当前菜单栏构建脚本保持一致。若只使用 Web，可以选择其他空闲端口；菜单栏不会自动跟随另一个端口。

页面显示“本地服务已连接”代表浏览器已经连到该服务，不代表麦克风正在录音。侧栏会另外显示采音状态和本地模型状态。

服务仅绑定本机回环地址。无需把端口开放到路由器，也不需要云端 ASR API Key。

### 2.2 停止不同入口启动的录音

| 启动入口 | 正确停止方式 | 说明 |
| --- | --- | --- |
| Web / 菜单栏开始监听 | 点击任一连接到同一后端的“停止监听” | 先停止麦克风，已录片段仍可能继续识别 |
| CLI 前台 `record` | 在该终端按 Ctrl+C | 保存有效末段并退出 |
| CLI 后台 `start` | 在同一资料库执行 `./scripts/audio-agent stop` | 校验进程身份，不向无关进程发信号 |
| 只想关闭 Web 服务 | 在前台服务终端按 Ctrl+C | 服务停止其自己管理的会话并收尾任务 |

**关闭浏览器、合上弹出面板、退出菜单栏，都不能代替“停止监听”。** 菜单栏退出只关闭客户端，后台服务及已开始的监听继续运行。若状态显示仍有片段待识别，等任务完成后再退出服务或切换资料位置。

## 3. Web 侧栏导航

| 入口 | 可以做什么 |
| --- | --- |
| 转写文档 | 开始/停止监听、调节录音设置、查看完整文字、复制和下载 |
| 声纹与人物 | 查看本人/其他人物、选参考录音、分析、试听、登记、编辑备注 |
| 录音文件 | 打开录音列表，搜索、筛选、试听、导入与手动转写 |
| 转写记录 | 查看和搜索已完成转写，包括同一录音的历史版本 |
| 存储位置 | 查看路径、填入默认目录、明确复制资料并切换 |
| MCP 接入 | 复制 Claude Code / Codex 配置、查看工具和调用示例 |

这些入口在同一网页内切换。“录音文件”和“转写记录”会展开主文档下方的资料工具；另外三个设置页是独立视图。可以直接打开 `/#storage` 或 `/#mcp`。切换视图本身不开始录音、识别或人物登记。

## 4. 转写文档：开始一段口述

### 4.1 选择设备并开始

1. 展开“录音设置”。
2. 选择确切的麦克风设备。设备不在列表时，先连接设备，再点击设备列表旁的刷新。
3. 选择中文、自动识别或 English。已知说的是中文时可直接选中文。
4. 检查“启用语音检测（VAD）”。Web 初始默认勾选；依赖和模型未就绪时会显示原因。
5. 点击“开始监听并自动转写”。首次使用时按 macOS 的提示允许启动服务的应用或终端访问麦克风。
6. 等待页面从启动状态变为监听状态，再说话。系统收到输入不代表已经确认了声音段。
7. 说完后停顿。约 0.8 秒连续安静结束当前片段，之后本地模型开始或排队识别。

文字出现的总等待时间由**停顿判定 + 排队 + 模型加载/识别 + 界面刷新**组成。一直连续说话时，系统仍在保留同一段，不会每 5 秒提前显示一批字。

### 4.2 看懂状态

| 状态或提示 | 应如何理解 |
| --- | --- |
| 正在启动 | 服务正在连接选定麦克风，还没确认采集成功 |
| 正在监听、等待声音 | 已收到音频输入，目前没有确认有效声音段 |
| 正在录制声音段 | 当前声音达到条件，正在保留这一段 |
| N 段等待识别 | WAV 已保存，模型还在处理或等待锁 |
| 麦克风已停止，正在处理已录音频 | 不再采音，但文字还可能继续出现 |
| 等待本地引擎/说话人分析 | 同一推理资源正在被其他任务占用 |
| 无法启动、设备错误或模型失败 | 查看具体原因；不要假定录音仍正常 |

启动约 10 秒仍收不到 PCM 会报错并停止，不会悄悄替换成另一只麦克风。设备断开、系统睡眠或服务退出都会影响采集。

### 4.3 动态分段与静音

Web 与菜单栏的声音检测发生在写入文件之前。安静时只保留短暂、有上限的内存缓冲，不持续生成静音 WAV，也不为这些安静输入启动 ASR。

确认声音需要一定持续时间，短促的单个尖峰不一定触发。系统保留约 0.3 秒触发前音频，降低开头被切掉的机会；结束时只保留短尾音。片段长度由声音与停顿决定。

连续声音达到约 10 分钟的资源保护上限时，服务会保存当前已收到的片段并停止麦克风、显示错误；不会把这一机制当作定时切片继续录下一段。听到电视持续讲话时也可能达到这个保护条件。

### 4.4 停止与继续

点击“停止监听”后，若有有效声音正在录制，保存该末段并继续完成识别；若一直安静，则不生成空片段。正在收尾时先等待状态完成，再开始下一次监听。

刷新页面可恢复当前状态和文字。关闭页面不会停止后台监听，因此离开前应主动检查停止状态。

## 5. 调节收音门槛和 VAD

### 5.1 门槛的含义

门槛是数字音频的 dBFS 值，范围 −60～−18。数字越低越灵敏，数字越高越不容易被小声触发。它不是房间噪音的声压分贝，也不能换算为“只录 1 米以内”。

Web 提供三个试调起点：

| 预设 | 数值 | 用途与代价 |
| --- | ---: | --- |
| 轻声敏感 | −50 dBFS | 较容易录到轻声，也更容易录入背景声音 |
| 默认 | 约 −44.4 dBFS | 初始起点，仍需按麦克风现场调整 |
| 近讲保守 | −32 dBFS | 对较小背景声更保守，也可能漏掉轻声或远处对方 |

建议先在正常摆放位置观察安静背景，再用正常音量说一句话，比较两者输入电平，然后小幅调整。Web 拖动后需要点“保存门槛”；菜单栏滑块松手后自动保存，也提供“默认”“较高”起点。

近 1 秒平均电平便于观察，触发仍由更短的声音帧决定，因此平均值低于门槛时也可能出现短时越线。保存时不打开麦克风。监听过程中可以更改门槛；正在录制的声音段使用旧值到结束，新值在段落间生效，界面会区分已保存值、当前值与待生效状态。

### 5.2 VAD 的作用

启用 VAD 后，在声音门槛之外使用本地 Silero 模型检查语音活动。模型只在明确开始的该会话中运行。缺少 VAD 模型或运行依赖时，界面会报错，不会自动退回另一种模式；如确实只需要能量检测，可显式取消勾选再开始。

电视台词、广播与旁人说话也是语音，VAD 不能可靠排除。提高音量门槛也不能判断说话人的身份或谈话关系；两种声音一样响时，没有一个纯音量阈值可以正确区分它们。

个人口述可让麦克风更靠近本人，双人谈话则要兼顾双方。单纯只保留本人声纹会丢掉对方的发言，本项目当前不会这样自动过滤。识别、声音检测与人物模型的区别见[模型说明](models.md)。

## 6. 查看、复制和导出完整文字

### 6.1 主文档范围

“全部记录”显示当前保留期内的完整文档；“本次监听”只显示当前 Web 后端会话。服务重启后，当前会话会重置，已保存文字仍可在全部记录中查看。

正文按录音时间最新在前，不截断为几行，也不只取最近 10 条。界面自动读完分页再形成全文。新结果不会强制把正在阅读的位置滚回顶部；选择旧文字时，会在需要时提示“有新转写”，由用户决定查看最新内容。

同一录音重新转写后，主文档只展示最新版本。要找旧版本，请进入“转写记录”。新转写保留真实录音起止时间；极早期缺少元数据、原音频又已经清理的记录，显示时间可能只能回退到转写完成时间。

### 6.2 各复制与下载按钮的区别

| 操作 | 复制/下载内容 |
| --- | --- |
| Web 正文单段“复制” | 这一段的完整原文 |
| Web “复制全部” | 当前范围全部完整原文，含每段录音日期与起止时间 |
| Web “下载全文” | 与全文复制同一份文字，生成 TXT 文件 |
| 录音详情“复制文字”/“下载 TXT” | 当前所选转写的完整原文 |
| 菜单栏单段复制 | 该段完整文字与人物标注 |
| 菜单栏“复制全部” | 当前保留的全部完整记录、时间和人物标注，不受搜索筛选影响 |
| 菜单栏“复制搜索结果” | 仅当前搜索匹配记录及其人物信息 |

Web 上可见的人物标签不会替换原始文字；当前 Web 的原文复制/下载与菜单栏的带标注复制有上述区别。

完整快照没有成功读完时，“复制全部”会暂时禁用。已有文字仍可阅读，但不能把已加载的一部分冒充全文。点击刷新，待错误消失后再复制。浏览器拒绝剪贴板访问时，可手动选中文字或下载 TXT。

TXT 是点击下载时生成的，保存到浏览器选择或默认的下载目录。每次识别本身只写入转写 JSON，不会在资料库中自动创建一份 TXT。

### 6.3 搜索

- Web “录音文件”可按名称或来源搜索，并筛选全部、待转写或已转写。
- Web “转写记录”可搜索文字，查看不同转写版本。
- 菜单栏可按文字、录音名称和说话人名字/备注搜索；它是文本匹配，不是语义问答。

## 7. 录音文件与转写记录

### 7.1 导入 WAV

1. 从“录音文件”点击导入，或在“声纹与人物”页点击“导入 WAV”。也可将 WAV 拖到网页。
2. 等待导入完成。相同源内容会按哈希去重，可能直接打开已有录音。
3. 在详情试听，确认文件是预期内容。
4. 选择语言，点击“本地转写”。导入本身不启动 ASR，也不自动触发说话人分析。
5. 转写完成后，文字加入主文档；需要人物区分时再手动分析。

Web 目前只接收 WAV，单文件上限 512 MiB。兼容格式通过本地 ffmpeg 转为 16 kHz、单声道、PCM16，生成受管理副本；源文件不被修改。此副本服务于识别，不是原始多通道、高位深素材的无损归档。

较长文件可能需要更长推理时间或超过超时。说话人分析有独立的 600 秒文件上限；这不等于 WAV 导入或单文件 ASR 也只有同样的时长上限。

### 7.2 试听与时间定位

选择录音后可使用音频播放器；转写中有时间戳时，点击可以从对应位置开始播放。“试听此人”播放该说话人的首个检测区间，方便核对身份；不是自动合并播放此人的全部话语。

音频不可播放但文字仍在时，可能是 WAV 已过期、被移走或访问失败。先查看录音时间和保留设置，不必为了显示文字而重新识别。文字和音频各有保留判断，二者可能不同时消失。

### 7.3 重新转写与排队

重新转写会产生新版本。主文档按录音去重，转写记录保留当前有效历史。模型资源忙时，任务可能排队或明确拒绝第二个手动任务；不要反复点击提交。

ASR 与说话人分析使用共享本地推理锁，标签分析不会与另一份 ASR 同时争用该锁。等待标签不代表原文丢失，失败也不会自动删除原来的成功转写。

## 8. 声纹与人物

### 8.1 区分这一份录音的说话人

从主文档某段旁点击“区分说话人”，会打开人物页，并在尚未分析时提交这一段的本地分析。已经分析过的记录显示“说话人”，可打开已有结果。也可以在人物页下方选择录音，点击“分析说话人”。

默认自动估计人数。如果知道人数，可选择 1–10 人后重新分析。手动指定人数是一种约束，不证明自动估计准确。输入须有可用的已保存录音，最长 10 分钟。

结果包括发言区间、发言总时长和可用参考时长。**“说话人 1”只属于这份录音**；下一份中的同号不能直接认作同一人。跨人的 ASR 段落可能显示多位人物与“混合发言”，系统不会猜测哪一个字具体属于谁。段落不能完整对齐时，会保留全文并显示归属未对齐。

### 8.2 登记本人为“我”

1. 在人物页选择一段自己独自说话、声音清楚的录音；每条清晰 10–20 秒是建议，不是登记门槛。
2. 完成说话人分析，找到自己的声音。用播放器或“试听此人”核对。
3. 点击“登记为我”。按钮可以直接打开表单，不要求先点某个特定播放按钮解锁。
4. 勾选已试听、确认是本人清晰单人声音，并同意按所选方式在本机保存声纹的确认项。
5. 选择保存方式后确认。网页默认**追加参考**，保留已登记样本；只有明确选择替换，才把整组本人参考换成当前这一条。

本人最多保存 **10 条参考**。可以先选 3–5 段平时常见的说话方式，例如普通讲话、轻声和较快语速；每条都应是本人清晰、没有其他人重叠的声音，并逐条试听确认。这是选样建议，不是数量要求，也不保证样本越多越准。不要把同一声音重复登记来凑数量。

优先选择不同录音中的独立参考，无需反复分析同一段来追加。同一录音重新分析后会产生新的分析版本，再追加可能被保存为新样本并重复计权；去重只限同一分析版本中的同一说话人。

登记**没有固定最低秒数**。1–2 秒的清晰声音，只要提取到了有效向量，也可以登记；提取失败则需要重新分析或换更清晰的参考。短参考可能让后续匹配不够稳定。追加只保存这次主动确认的参考，不会自动收集后续讲话，也不重新训练模型。

本人参考列表可以单独移除某一条；其余样本保留。点击“清空本人样本”则取消全部本人登记，原录音、原文和匿名分析保留。移除最后一条也会变为未登记。达到 10 条后，先检查并移除不合适的参考，再追加；系统不会自动淘汰旧样本。原录音即使过期无法试听，已明确登记的样本仍保留，直到主动移除。

重新分析后，旧确认版本会失效，需要重新核对。不得把自动分析出来的某个人直接当作已获本人登记授权；同一份分析中的不同说话人也不能都登记为“我”。旧版本已有的一条本人参考仍保留，读取时不会擅自替换或追加；主动修改登记后才升级为多参考格式。

### 8.3 给其他人物填写名字和备注

1. 选中并分析录音，试听要登记的人。
2. 点击“登记其他人物”。
3. 选择新人物，填写 1–80 字姓名和最多 200 字的可选备注，均为单行文字。
4. 勾选已试听并确认，保存。

人物以“名字 · 备注”显示，例如“同事甲 · 设计讨论”。“我”保留给本人参考，其他人物不要用这个名字。人物列表可编辑姓名/备注；这不会修改原始转写正文。

**其他人物仍是每人一条参考**，不使用本人的多样本流程。要改善参考，可选一份更清晰的新录音，在登记对象中明确选择替换某个现有人物的参考声纹。若这一声音已经绑定另一人物，先核对并移除冲突绑定，系统不会静默把两个人合并。

“移除”需要确认，会删除该人物的本地参考和备注，不删除录音、原文或匿名分析。备注是用户自己填写的信息，模型不会替你推断某人的身份或关系。

### 8.4 理解后续匹配

后续分析会尝试与同一模型生成的参考声纹比较。用户明确绑定的声音可显示为已登记人物；其他录音中的推断会加“声纹匹配”，需要核对。余弦相似度不是身份认证概率。

本人多条参考按有效语音时长加权综合比较，并不会挑一条最高分来强行认人；录错或质量差的参考可能降低效果，可以逐条移除。每条超过 10 秒后不再增加比较权重，但选择清晰、连续的语音仍有助于取得稳定参考。模型不同的参考不混合比较。

很短、重叠、噪声大或麦克风差别明显的语音可能保持匿名。当前自动比较要求被分析说话人有足够参考语音，约 2 秒；登记成功不代表每一个后续短句都能匹配。人物标注不用于丢弃未匹配声音，也不实现声源分离。

### 8.5 自动区分新录音

在主文档“自动区分说话人”中开启开关。开关默认关闭，保存到本机资料库。开启后：

- 仅监听会话中新产生、刚成功完成 ASR 的片段进入分析队列。
- 已在运行的会话，其之后的新片段也会使用当前开关，不必重启监听。
- 原文先显示，标签稍后补上；排队时可继续阅读。
- 不扫描历史转写、不自动处理导入文件、不自动登记任何人物。
- 关闭后停止新增自动任务；已经排队的任务可以完成。

只是打开人物页、刷新状态或查看已有分析，不会运行模型。更具体的模型条件与误差范围见[模型说明](models.md)。

## 9. 存储位置与保留规则

### 9.1 默认位置

未手动指定或保存其他目录时，默认使用项目 `.data/`。在“存储位置”页可看到本机解析后的完整路径：

| 资料 | 默认相对位置 | 说明 |
| --- | --- | --- |
| 受管理 WAV | `.data/clips/` | 规范化副本 |
| 转写 JSON | `.data/transcripts/` | 全文、时间、语言与识别信息 |
| 单录音说话人分析 | `.data/speakers/` | 随对应录音清理 |
| 本人参考 | `.data/voiceprint.json` | 最多 10 条，直到主动逐条移除或取消全部登记；向量不发送到网页 |
| 其他人物 | `.data/speaker-profiles.json` | 姓名、备注与私密参考 |
| 门槛/自动分析设置 | 当前库中的设置 JSON | 同一后端的 Web 与菜单栏共享 |

本机存储目录设置另保存在 `~/Library/Application Support/Audio Agent/storage.json`，该文件不存录音。CLI 参数、环境变量或已保存设置可能让实际库位于其他位置，以页面展示为准。完整优先级与文件清单见[存储与隐私](storage-and-privacy.md)。

### 9.2 复制资料并切换

1. 停止监听，等待已录片段的 ASR、说话人分析和导入完成。
2. 关闭正在写入旧资料库的其他 CLI/MCP 客户端；同库外部采集或模型锁也会阻止迁移。
3. 打开“存储位置”或 `/#storage`。
4. 输入本机绝对路径，以 `/` 开头，不使用 `~`。自定义目标的父目录须已存在，目标本身须为空或尚不存在；不能与旧库互相包含。
5. “使用默认目录”仅把接口提供的项目 `.data` 路径填入输入框，不立即搬动资料。
6. 阅读说明，主动点击“复制现有资料并切换”，等待复制完成。
7. 确认页面显示新路径、复制统计，试听一段录音并查看文字。
8. 重新连接其他 CLI/MCP 客户端；MCP 重新建立增量游标。需要再次录音时主动点击开始。

迁移复制数据库、WAV、转写 JSON、说话人分析、人物参考/备注及声音设置。模型、日志、缓存和测试资料不随库迁移；模型默认位置与资料库选择分开管理。

成功后旧目录保留为副本，不自动删除，也不允许旧客户端继续写入。新库的保留清理不会替你清理旧副本。非空目标会被拒绝，不覆盖或合并；复制或写配置失败会回滚，保持原运行库可用。失败时表单输入保留，先读错误原因再重试。

如果默认目录已经有资料，不能用迁移按钮强行覆盖它。需要切换已有库、恢复备份或跨 Mac 搬迁时，按[存储与隐私](storage-and-privacy.md)处理。

### 9.3 24 小时不是长期归档

默认保留 24 小时。采集片段按结束时间 `end_time` 判断，导入片段按入库时间 `created_time` 判断，避免旧 WAV 刚导入就过期。转写 JSON 的磁盘清理单独依据文件修改时间 `mtime`，较新的文字可能在原录音清理后继续保留；读取时还会按记录时间筛选。逐录音说话人分析随对应录音清理，本人/其他人物参考则保留到主动移除。具体触发点见[存储与隐私](storage-and-privacy.md)。

过期记录不再由 Web 当作可用资料展示。实际磁盘清理由运行中的相关写入/清理流程执行；所有进程退出后，没有独立系统定时器替你准时删除文件。可显式运行：

```sh
./scripts/audio-agent prune
```

清理针对本项目管理的副本，不删除原始导入文件。重要文字请及时下载 TXT，重要原音频请保存原文件；复制全文是当前保留记录的导出，不是永久全部历史。

### 9.4 更换 Mac

这不是自动同步功能。本机路径设置不会把文件传到另一台电脑；另一台仍需项目代码、兼容依赖和本地模型。项目路径变化后要重新构建菜单栏应用、重新生成 MCP 绝对启动路径。不要把旧电脑路径原样复制当作可用配置。具体步骤见[安装与启动](installation.md)和[存储与隐私](storage-and-privacy.md)。

## 10. MCP 接入页

打开侧栏“MCP 接入”或 `/#mcp`。页面显示当前本机 Python 路径、资料库说明、Claude Code / Codex 配置、检查命令、工具表和读取示例。

1. 在顶部“MCP + Skill 一键接入”选择当前项目或用户级范围。
2. 点击对应客户端的“复制完整安装指令”，粘贴给本机 Codex 或 Claude Code 执行。它会合并 MCP 配置并安装配套 `audio-agent` Skill；当前项目指目标客户端的实际工作区。下方“复制配置”仍供手动配置使用，不包含 Skill 安装。
3. 按客户端要求确认项目或服务信任并重新加载。
4. 在客户端检查实际连接状态。页面不会替你探测 Claude Code / Codex，也不会把配置已显示当成已连接。
5. 读取已转写文字时用 `audio_recent_transcripts` 或 `audio_get_updates`；只有需要识别已保存音频时才用 `audio_transcribe_*`。

完整安装指令、配置、检查命令和调用参数的复制按钮都只写剪贴板；浏览器不执行安装。安装文档可在[Agent 一键接入](agent-setup.md)独立阅读或整段复制。stdio 由客户端启动，不把浏览器的 HTTP 地址配置成 MCP 服务地址。

`audio_get_updates` 需要客户端主动请求：首次不带游标，之后传入 `next_cursor`；同一 `document_key` 的更新覆盖旧条目，不重复追加。服务重启或换库后丢弃旧游标重新建立。它不是自动推送，也不会自行唤醒客户端模型。

首次增量默认仅取最近 20 条、最多 100 条，不补全部旧历史。需要完整保留期内的全文时使用 Web 文档导出，而不是反复重建游标。

本地识别不上传录音，但调用方读取的文字会进入该客户端的模型上下文。仅复制或安装配置不会自动发送全部历史。完整操作见[MCP 接入](mcp-integration.md)和[MCP 使用](mcp-usage.md)。

## 11. macOS 菜单栏操作

### 11.1 构建与打开

项目环境准备好后：

```sh
./scripts/build-macos-app
open "dist/Audio Agent.app"
```

它只显示菜单栏波形图标，没有 Dock 图标或独立主窗口。当前构建依赖本项目 `.venv` 与已配置模型，记录项目绝对位置；不是拷走 `.app` 就能在另一台 Mac 独立使用的安装包。没有自动设置登录自启。

明确启动应用时，若本项目后端未运行，会尝试启动本地 Web 服务；这个动作不打开麦克风或执行 ASR。遇到端口被别的程序使用或资料库不一致时会提示，不自动关闭别人的服务。

### 11.2 高频操作

| 操作 | 位置与行为 |
| --- | --- |
| 开始/停止 | 面板顶部大按钮；右键图标也可操作 |
| 换输入设备 | 开关下方的输入设备选择；忙碌时锁定 |
| 调门槛 | 收音门槛滑块，松手保存；默认/较高为快捷起点 |
| 查文字/人物 | 搜索框匹配完整文字、名称、人物标签与备注 |
| 复制一段 | 对应段落的复制按钮，含人物信息 |
| 复制全部 | 不受当前搜索筛选影响；完整快照读取成功才启用 |
| 复制搜索结果 | 有搜索词时出现，仅复制匹配记录 |
| 高级设置 | “打开控制台”进入 Web 的设备、VAD、人物及 MCP 等功能 |
| 更改存储 | 底部“存储位置”打开 Web 对应页 |
| 退出 | 仅退出菜单栏客户端，后端继续运行 |

新的后端会话默认中文与 VAD；连接到已有会话时沿用其语言/VAD设置。要更改这些选项，到 Web 录音设置中停止后选择再开始。菜单栏共享同一门槛设置，不是另一份独立音量参数。

菜单栏没有独立 VAD 开关。没有兼容 Silero v4 模型时，应先在 Web「录音设置」取消默认勾选的 VAD，并实际开始一次监听；菜单栏刷新后才沿用该会话的 `vad_enabled=false`。仅取消复选框不会把设置发送给菜单栏。这个选择不是持久化 VAD 设置：一个新启动的菜单栏连接尚无会话的新后台时仍默认启用 VAD；仍在运行且已经读取到关闭值的菜单栏可能继续保留内存选择，因此重启组合后应检查实际状态。安装步骤见[安装与启动](installation.md)。

首次点开始会请求 Audio Agent 的麦克风权限。若拒绝，在“系统设置 → 隐私与安全性 → 麦克风”中允许对应应用，然后再次开始。打开面板、读取文字和复制不会请求麦克风权限。

停止后，面板可能继续显示“正在处理 N 段已录音频”；这时已经不再录音。关闭面板或退出菜单栏不会发送停止命令。如果要结束当天记录，先点击停止并确认状态，再按需退出客户端。

## 12. CLI、目录监听与按需转写

### 12.1 检查与前台连续缓存

```sh
./scripts/audio-agent doctor
./scripts/audio-agent devices
./scripts/audio-agent record --device '设备列表中的精确名称'
```

`record` 前台运行，默认每 5 秒保存一片。Ctrl+C 停止。它不自动执行 ASR；另一个终端可以请求最近已落盘音频：

```sh
./scripts/audio-agent transcribe --seconds 30 --language zh --copy
./scripts/audio-agent transcribe --seconds 60 --last-utterance --copy
```

`--last-utterance` 用能量判断最近声音区间，噪声和音乐也可能被选中，不是语义上的“最后一句”。最近窗口须大于 0 且不超过 600 秒。若有缺录时间，结果会报告缺口，不伪造补齐内容。

后台模式：

```sh
./scripts/audio-agent start --device '设备列表中的精确名称'
./scripts/audio-agent status
./scripts/audio-agent stop
```

CLI 设备名称必须来自本机 `devices`。开始失败不会自动换麦；默认行为也不包含开机自启。

### 12.2 导入并转写现有文件

```sh
./scripts/audio-agent import-wav /absolute/path/recording.wav
./scripts/audio-agent clips
./scripts/audio-agent transcribe --clip 片段ID --language zh
```

将 `片段ID` 替换为列表中实际的 ID。导入命令只入库，不识别；指定 ID 转写不会接受任意未入库文件路径。

### 12.3 监听本地同步目录

```sh
./scripts/audio-agent watch /absolute/path/inbox
```

监听器递归检查 WAV，等待大小和修改时间稳定后导入，并按内容去重。默认跳过 `edit/` 与 `*_edit.wav`，避免同一 DJI 录音的原版和编辑版重复入库；确实需要可加 `--include-edits`。文件传送工具最好先写临时扩展名，完成后原子重命名为 `.wav`。

目录监听只处理已经能从本机文件系统读到的文件，不实现从 DJI 设备无线取回内录，也不自动转写新导入的文件。外部同步工具、接收器音频输入和本项目导入是不同环节。

## 13. 常见问题速查

| 现象 | 先检查 | 建议操作 |
| --- | --- | --- |
| 对着电脑说话但没文字 | 是否明确开始、设备是否正确、状态是否收到输入 | 先开始并看状态，说完留停顿；不要只等待页面自动开麦 |
| 持续说话很久都没出字 | 声音段是否一直没有结束 | 留一段安静时间，等待模型；当前不是逐字流式 |
| 一直没有生成片段 | 门槛是否过高、VAD是否报错、麦克风电平是否变化 | 降低一点门槛或核查设备/模型；不盲目无限降低 |
| 电视声音被录入 | 电视人声达到音量和VAD条件 | 调整拾音位置和门槛，必要时明确停止；VAD不判断谈话关系 |
| 启动按钮不可用 | 未连接、无设备、无 ASR/VAD 模型或正在收尾 | 查看具体状态，准备依赖或等待完成 |
| 本人登记按钮不可用 | 是否有有效声纹、分析是否完成、服务是否连接 | 分析更清晰录音；不是固定“必须5秒”的限制 |
| 登记后下一段还是匿名 | 新片段短、噪声/重叠、模型不同或匹配不充分 | 保留匿名并核对，可主动追加常见说话方式的清晰本人参考；数量增加不保证匹配成功 |
| 有“混合发言” | 同一 ASR 时间段覆盖多个说话人 | 回听核对；系统不会凭空逐字分配 |
| 全文复制变灰 | 快照分页未完成、更新失败或待应用新内容 | 刷新完整文档后再复制，旧文字不会因此丢弃 |
| 导入没触发转写 | 导入本身只保存文件 | 选择文件点击“本地转写” |
| 音频消失或无法试听 | 保留时间、文件是否移动、是否换了资料库 | 检查路径和时间，重要资料另行备份 |
| 找不到自动 TXT 文件 | 每次识别保存的是 JSON | 在 Web 点击下载全文或下载单条 TXT |
| 存储切换被拒绝 | 任务/锁仍忙、目录非空、父目录不存在或路径无效 | 停任务、使用新/空绝对路径，读取错误后重试 |
| 换库后 MCP 仍显示旧资料 | 旧 stdio 进程仍持有原库 | 重连客户端、重建游标，核对新配置 |
| 菜单栏退出后还在录音 | 退出只关闭客户端 | 重新打开菜单栏或 Web，主动停止监听 |
| 本地服务或菜单栏打不开 | 端口占用、项目移动、`.venv`缺失 | 不覆盖无关服务；检查启动日志或重新安装/构建 |
| MCP 页有配置但客户端无工具 | 仅生成/复制配置还不算加载 | 在客户端确认作用域、信任并重连，查看实际工具列表 |

详细诊断见[故障排查](troubleshooting.md)。资源占用和耗时判断见[性能与资源](performance.md)。需要调用接口或扩展功能时，使用[API 参考](api-reference.md)、[技术设计](technical-design.md)与[开发与验证](development.md)。
