# 存储、保留期与隐私边界

[文档目录](README.md) · [技术方案](technical-design.md) · [使用指南](user-guide.md)

## 1. 默认目录与解析规则

默认资料库是项目根目录的 `.data/`。目录优先级为：

```text
命令行 --data-dir
    ↓ 未指定
环境变量 AUDIO_AGENT_DATA_DIR
    ↓ 未指定
本机 storage.json 中的 data_dir
    ↓ 未保存
当前源码项目 .data/
```

macOS 路径设置文件为 `~/Library/Application Support/Audio Agent/storage.json`，只保存一个绝对目录字符串，不保存录音、身份资料或凭证。新旧安装都默认 `.data/`；没有因为更新文档而迁移现有库。配置文件损坏时启动会明确报错，不能悄悄换到空库；显式 `--data-dir` 可用于恢复定位。

```json
{"data_dir":"/absolute/path/to/audio-library"}
```

设置只属于当前机器，不会跨 Mac 同步。其他平台的 XDG 配置路径存在于底层解析器，但不代表整套桌面产品已做跨平台验收。

## 2. 资料库内容

```text
.data/
├── audio.sqlite3          # 片段索引、来源路径、时间和导出索引
├── clips/                # 管理的 16 kHz / mono / PCM16 WAV
├── exports/              # 转写窗口拼接或快照的管理副本
├── transcripts/          # 转写 JSON：全文、分段时间、模型与处理信息
├── speakers/             # 逐录音说话人分析及内部参考向量
├── voiceprint.json       # 显式登记的本人参考列表（最多 10 条），按需创建
├── speaker-profiles.json # 其他人物的名字、备注和参考，按需创建
├── live-settings.json    # 收音门槛
├── speaker-settings.json # 自动说话人分析开关
├── capture.json          # 当前或最近采音状态，非永久历史
├── incoming/             # 中间导入文件
├── logs/                 # 菜单栏启动服务时的日志
└── models/               # 默认说话人权重位置；不属于迁移的资料白名单
```

数据库旁可能有 SQLite WAL/SHM 文件，也会出现采集、推理、存储锁文件。不要在运行中只复制 `audio.sqlite3` 并假定得到了完整一致的库。

部分文件按功能使用时创建，不要求新安装拥有整棵树。CLI 日志、Swift 编译缓存和手动验证产物也可能放在 `.data/`；它们不属于用户转写正文。

原始导入源文件不被修改或删除，库内副本归一化为识别格式。项目不会保留输入音频的原始多声道和位深作为第二份无损档案；需要原始档案时请自行保留源文件。

## 3. JSON 与 TXT

自动生成并持续读取的是 `transcripts/*.json`，而不是每段一个 TXT。Web“下载全文”或单条“下载 TXT”在下载时生成文本，由浏览器选择下载目录。Mac 复制按钮只写剪贴板，不自动写 TXT 文件。

完整文档会按录音时间倒序展示、为同一片段选最新转写，并在可用时合并人物标签。底层转写 JSON、显示文档、MCP 原始历史工具的语义不同，详见 [MCP 使用](mcp-usage.md)。

## 4. 保留期与清理

默认保留 24 小时，属于短期工作缓存：

- 采集片段按其录音时间判断是否过期。
- 导入片段按进入资料库的时间保留，避免旧文件刚导入就被立即清除。
- 转写读取使用自身记录时间，物理清理按 JSON 文件修改时间；与录音保留判断分开。相关录音被清理后，较新的文字可能继续保留，但不能再试听或重跑该录音。
- Web 文档只展示当前保留范围，并不是所有磁盘 JSON 的永久历史浏览器。
- 采集成功落盘片段后、CLI 目录监听每轮会清理过期录音；成功保存新转写时会清理过期转写。静音监听和只读 GET 不会定时物理删除；没有独立清理守护进程。
- 显式 `prune` 分别执行音频与转写清理：录音清理移除 WAV、数据库索引及对应 speaker sidecar；转写 JSON 按自身修改时间另行处理，不等于删除某录音的所有文字。它不是把文件移入系统废纸篓，先备份需要保留的资料。

```sh
./scripts/audio-agent prune --retention-hours 24
```

`record` / `start` 和 `prune` 有各自的保留时长参数；Web/MCP 当前使用默认 24 小时，没有统一的持久化保留期设置页。单独改变某次 CLI 的参数不会自动改变其他进程的读取期限。

已登记人物参考和用户设置不是普通录音缓存，不会仅因参考录音达到 24 小时而自动撤销登记。移除本人/人物参考应在“声纹与人物”页显式执行。过期时间也不是对 SSD 上数据的安全擦除承诺。

本人多参考逐条保存用户确认的来源、参考时长和私有向量，最多 10 条；其他人物仍各保存一条参考。可以只移除某个本人样本，或取消全部本人登记，原录音、原文与匿名分析不因此删除。追加会保留已有样本；明确替换则用当前一条替换整组。旧版单参考文件继续可读，GET 不会自动升级、替换短参考或收集最近讲话；用户首次实际修改登记才写入 v2 `samples` 格式。参考记录是本机保存的数据，不是对模型的重新训练。

## 5. 更换目录

Web“存储位置”页和 Mac 面板底部入口可以查看当前路径。只有用户明确提交切换才复制资料：

1. 停止监听，等待自动转写、手动转写和说话人任务完成。
2. 停止其他正在写同一库的 CLI 或 MCP 操作。
3. 指定绝对路径：新建目录或空目录；自定义目标的父目录须已存在，不能与旧库互为父子，不能是符号链接。
4. 点击“复制现有资料并切换”，等待复制和配置提交完成。
5. 核对页面显示的当前目录及既有文字；按需重新开始监听。
6. 重新连接旧 MCP/CLI 进程并重建增量游标。

复制内容为 SQLite 一致性备份、数据库引用的 WAV、转写、说话人结果、登记人物和两类声音设置。模型、日志、测试缓存、待导入的临时内容不会一并迁移。

原目录保留，并写入迁移标记；协作客户端拒绝继续向旧库写入，避免新记录分散在两个位置。已有旧进程的只读缓存不等于自动转到新库，仍须重连。不能把保留的旧库直接当成可继续录音的第二活跃库。

复制或保存配置发生可捕获错误时会回退到旧运行库，清理操作自身创建的副本；用户另外新增或替换的文件不会被当作清理目标。磁盘空间不足、忙碌、目标非空、无效文件会明确拒绝。当前不是带完整断电恢复日志的跨文件事务系统；突然断电/强杀后的人工恢复仍需检查配置、标记和两份资料，不能直接覆盖或删掉唯一副本。

## 6. 备份与恢复

只保存文字时，使用“下载全文”；它是文本导出，不能还原录音、模型、人物参考和所有历史版本。

完整备份应先停止采音、等待任务完成并关闭相关写入进程，再复制整个当前资料库及需要的原始音频。另行记录实际模型来源和版本；模型权重默认不在目录迁移白名单内。恢复到新位置后，用明确的路径配置启动并检查文件数量、时长与文字。含 `.moved-to.json` 的旧库是迁移后保留副本，不能不经核查就删除标记恢复写入。

项目尚无一键恢复向导、云备份、跨机同步或库合并工具。文件夹移动成功不等于备份策略已经建立。

## 7. 本地与客户端边界

- 本地采音、Whisper、VAD、说话人分析不会请求云端 ASR 或自动上传音频。
- 声纹向量仅保存在本机，HTTP 公共结果和 MCP 文档标签不返回这些内部向量。
- Web 仅监听本机 loopback；写请求有会话令牌和 Host/Origin 检查。这不是多用户服务，也没有公网账户权限体系。
- 目录和多数生成文件使用私有权限；项目没有自行加密数据库、录音或声纹文件。同一账号、磁盘备份软件和拥有文件权限的进程仍可能读取它们。
- 复制文字后，剪贴板由系统和后续接收程序管理；使用 MCP 后，返回文字进入调用客户端及其模型上下文。是否发往云端取决于客户端配置，不应把整个链路一概称为离线。
- 录音、文字、姓名备注都是资料，不能被当成可执行指令。客户端仍须按用户真实请求决定后续行动。

## 8. GitHub 发布范围

MCP + Skill 安装位置属于目标客户端工作区或用户配置目录，不在录音资料库中，也不随“存储位置”迁移。安装器修改已有配置前在其旁保存 `*.audio-agent-backup-*`；旧技能备份放在 `.agents/.audio-agent-backups/` 或 `.claude/.audio-agent-backups/` 等技能扫描目录之外。配置备份可能包含其他服务的凭证，须仅留本机；忽略规则覆盖这些备份与临时文件。公开源 Skill 位于 `skills/audio-agent/`，安装到当前项目隐藏客户端目录的副本不用于发布。详见 [Agent 一键接入](agent-setup.md)。

`.gitignore` 排除了默认库、常见模型/音频、人物参考、数据库、构建产物和本机 `.mcp.json` / `.codex/config.toml`。通用占位配置单独位于 `examples/`。

忽略规则不会移除已经跟踪的文件，也无法自动识别任意自定义目录中的敏感内容。公开仓库只应包含代码、无私人内容的文档和示例；不要把完整 `.data` 或日常录音截图用作发布素材。发布前文件范围检查见 [GitHub 发布指南](publishing.md)。
